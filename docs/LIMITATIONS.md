# Current limitations

W0 bootstrap provides an inert status command, offline status demo and bounded staged/index secret guard. The guard detects forbidden credential/agent paths, private-key headers, recognizable provider-key strings and long literal credential assignments. It is a bounded defense with planted controls, not a guarantee that every possible secret format is detected.

Generic Source/Finding/Pointer/Resolution models, strict full-triple registry/protocols and generated schemas exist. They are structural metadata, not source readers or truth/approval verifiers. No concrete line/region/report/product/row resolver, dependency analysis, provider implementation, five-dependency fixture, semantic gold, generated upgrade results or full paid comparison exists yet. Event/metric tuples have null locators pending exact owner field schemas and cannot resolve even if a protocol is registered. Actual producer acquisition, excerpt/page/geometry/access/deletion conformance and model/API access/pricing/live usage remain unverified. Public real examples require licence/source receipts. Only actual executed checks may be reported as passed.

There is no listener, database service, browser API key, Docker image, cloud deployment or public release. The Python/Node core needs local execution. A future self-contained report may be hosted statically, but this checkpoint includes no checklist viewer.

The optional supplied-memory library resolves actual immutable text line/section evidence under caller policies, with mandatory-evidence downgrades. The npm core reads supplied manifest/lock/catalog buffers and uses installed semver7.8.5 for version/range/window facts; neither library is wired into application analysis yet. No source acquisition, advisory membership/fetching or human/semantic verification follows from these foundations. Runtime failures stay incomplete and do not become negative upgrade facts. Independent gold/campaign/foreign-source gates are unchanged.
